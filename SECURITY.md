# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| latest  | :white_check_mark: |

## Reporting a Vulnerability

If you discover a security vulnerability in Tomotoken, please report it responsibly.

**Please do NOT open a public GitHub issue for security vulnerabilities.**

Instead, please report vulnerabilities via GitHub's private vulnerability reporting:

1. Go to https://github.com/cawa102/tomotoken/security/advisories
2. Click "New draft security advisory"
3. Fill in the details of the vulnerability

### What to include

- A description of the vulnerability
- Steps to reproduce the issue
- Potential impact
- Suggested fix (if any)

### Response timeline

- **Acknowledgment**: Within 48 hours of the report
- **Initial assessment**: Within 7 days
- **Resolution target**: Within 30 days for critical vulnerabilities, 90 days for others

### Disclosure policy

- We follow coordinated vulnerability disclosure practices
- We will credit reporters in the fix announcement (unless anonymity is requested)
- Please allow us reasonable time to address the vulnerability before any public disclosure

## Scope

The following are in scope for security reports:

- The Tomotoken application code
- Dependencies with known vulnerabilities
- Configuration issues that could lead to data exposure

The following are out of scope:

- Issues in third-party services (Hyper3D, Anthropic API, OpenAI API)
- Attacks requiring physical access to the user's machine
- Social engineering attacks
